# Design record — Install, backup, drift

**Date:** 2026-09-21 · **Initiative:** 02-install-and-drift · **Owner:** delivery lead
**Status:** Written after the fact, and saying so

## Why this record exists, and what is honest about it

`collaboration.md` §2 makes this initiative architectural: six new contracts, the first authority
boundary that writes outside the repository, new scope lines, and a reversal of a spec behaviour. The
design gate is therefore owed an artifact, and the first draft of the plan shipped without one.

**The ideation did happen.** Six scope questions were put to the user on 2026-09-21, each with two or
three alternatives carrying their costs, and each answered. What did not happen is the writing-down —
the same gap R35 conceded for T-10: *"the missing thing is the artifact and the gate, not the
agreement."* This record closes it, and is dated for when it was written rather than backdated to when
the conversation happened.

## The shape

The library is canonical (D1); a target is derived and overwritable. 02 makes that write **inspectable
before it runs, reversible after it runs, and incapable of destroying a file it did not put there.**

Three ideas carry the whole design:

**1. A verdict is a pure function of three hashes.** What the library has, what the manifest says was
installed, what is on disk now. Everything else — backups, refusal, rollback, drift reporting — is a
consequence of the verdict, so the verdict function is written first, with no I/O, and table-tested
across all eight combinations including the three that violate transitivity and must raise.

**2. The manifest is the only thing that makes any of this reversible.** It lives outside both trees,
records per-file hashes and the library's git SHA, and is keyed by target path. Without it there is no
"what did we install", no `LOCAL_EDIT` detection, and no honest rollback.

**3. Foreign means foreign.** A path in the target that the library and the manifest both disown is
never touched, never pruned, never overwritten. This is the rule that would have saved the `.swp` file
and reported the `node_modules` tree instead of copying it into canon — the incident that started the
whole project.

## Decisions taken with the user, with their rejected alternatives

| Question | Chosen | Rejected, and why |
|---|---|---|
| Install targets | `--target PATH`, any directory (**R43**) | A single hard-coded target — adding one later means revisiting the manifest and every signature. Named targets in config — config surface for one real target |
| Claude Code's `synced/` bucket | Already `FOREIGN`; no rule (**R44**) | A named exclusion silently hides whatever else lands there. Suppressing its V1 suppresses a true finding to tidy a report |
| Plugin-format export | Out of 02; plain zip (**R45**) | Building it alongside install shares packaging code but widens one coherent job into two risk profiles, with no consumer yet |
| Symlinked artifact root | Warn on scan, refuse on install (**R46**, **R53**) | Follow-and-materialise needs cycle detection and replaces a link with files. Warn-only splits one question across two initiatives, which R38 existed to avoid |
| Non-Claude harness layouts | Out of scope; MCP covers it (**R47**) | Pluggable layouts are one moving target per tool with no test signal when an owner changes theirs |
| Behaviour on `LOCAL_EDIT` / `CONFLICT` | Refuse, print the plan, require `--resolve` (**R48**) | Interactive prompting hangs unattended and needs a second CI path. Back-up-and-overwrite turns "I edited that" into a restore operation |

## Decisions taken by the delivery lead

| # | Decision | Why it is not a specialist's |
|---|---|---|
| **R50** | Concurrency: a single-writer advisory lock, `O_EXCL` sentinel beside the manifest | Charter §12 is orchestrator-owned standing convention, and this is risk acceptance about the user's live harness |
| **R51** | `T-N` and `F-N` are project-wide and never restart | `plan-formats.md` §8 already required it; the first draft restarted both and collided inside its own tables |
| **R52** | `MANIFEST_REPAIR` is a distinct verdict | A consumer must be able to count it; 03 renders verdicts as a drift view |
| **R54** | `--resolve` ships in 02 | A refusal with no resolution path is a dead end |

## What this initiative deliberately does not do

- No three-way merge UI. Choose a side, or open both in `$EDITOR` (spec §8.5).
- No plugin format, no non-Claude layouts.
- No install into a target the user has not named.

## The risk that shapes everything

**This is the first initiative that writes outside the repository.** A defect here destroys the user's
working harness. Hence: backup before any write, refuse the apply if the backup cannot be taken, and
`~/.claude/` is never used as a test target — a target fixture is committed instead.
